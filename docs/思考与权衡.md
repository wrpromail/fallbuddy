# 摔友记 · 思考与权衡

> 本文记录「为什么这样设计」：核心思路、十个关键决策的理由与代价、已知债务、优化路线。系统结构本身见 [架构设计](架构设计.md)。

## 1. 核心思路：mock 是云函数的可执行规格

V0 最反常规的决定是：**先按真实后端的标准写本地 mock，而不是「先糊一个能跑的 demo，接云时再重写」**。理由：

1. **契约先行**：`ApiResponse` 信封、错误码、参数签名在写页面之前就定型，页面与业务规则同步成型，而不是页面先按想象写、后端再迁就；
2. **规则可执行**：权限、限频、幂等、事务这些「纸面规则」在 mock 里真的执行，28 项测试让每条规则可以被反复验证，而不是文档里的一句承诺；
3. **迁移成本最小化**：V1 只新建 `services/cloud/` 适配器替换门面指向，页面零改动。

这份「规格」有三层：类型签名（`shared/types.ts`）、规则实现（`services/mock/api.ts`）、回归测试（`tests/services.test.mjs`）。V1 写云函数时，三层就是逐行可对照的验收标准。

代价是 V0 的 mock 比一般原型「重」得多——限频、脱敏、幂等这些在纯演示里毫无必要。这笔投入的回报在 V0.2 已经兑现了一次：发现 `publish` 缺枚举校验后，修复落在 `shared/validation.ts` 一处，mock 与未来云函数同时受益。

## 2. 十个关键决策

每个决策都按「选择 → 为什么 → 代价与边界」记录：

| # | 决策 | 为什么 | 代价与边界 |
|---|---|---|---|
| 1 | 原生 WXML/WXSS/TS，不用跨端框架 | 小包体、平台组件保真、低依赖（方案 §8.1）；个人项目依赖越少越可控 | 放弃 React 生态复用；组件属性类型只能靠断言 |
| 2 | 业务规则全在服务层，页面保持「笨」 | 权限/限频规则只写一份、只信一处；V1 换后端页面不动 | 页面要做一层 view-model 转换；组件与服务端的规则偶有重复（reaction-bar 的禁用逻辑），需靠测试防漂移 |
| 3 | Incident 与 Story 分离 | 事实字段（运动/部位/原因）不因文案编辑而改变，AI 润色（V1.1）永远不能覆盖事实 | 发布表单字段更多；数据模型多一层 |
| 4 | 动画是展示层，服务端事实不依赖动画完成 | 弱网/低端机/减动效时静默降级不丢数据；历史事件靠 `animationVersion` 可回放 | 动画与互动「感觉」绑定松散，需要 pending→成功→播放的编排 |
| 5 | 素材由代码生成，不是手拖图层 | 改色/比例/表情后 `npm run assets` 可复现；热点与锚点随导出同步生成，不会和视觉漂移 | 美术表达受几何约束，做不出手绘质感 |
| 6 | `requestId` 幂等只盖 4 个写（publish/gift/claimWeekly/react），其余靠状态机/版本锁 | 重复副作用只存在于这四处；全盖会显著增加 mock 与测试复杂度 | 云函数必须重新评估每一处（见 V1 设计补充 §12.2），这是文档化的有意偏差 |
| 7 | `operations` 本地缓存不是账本 | mock 能证明「重试不重复」，**证明不了「并发不超发」**——这是本地 mock 与真实数据库的本质分界 | 并发赠礼的验证只能留到云端做；文档显式声明防止照搬 |
| 8 | 预览器是平行 DOM 实现（~2800 行） | 没有 DevTools 也能开发与回归视觉交互；素材/种子与小程序同源 | 平行实现意味着「预览过 ≠ 小程序过」；真机缺口只能显式记录为遗留项 |
| 9 | 匿名只做 ID 脱敏，保留外观 | 小圈子里强行中性化头像会牺牲产品核心视觉；是否升级为中性头像是产品决策不是技术决策 | 诚实承认「小圈子内仍可能通过外观识别」，不假装匿名是完美的；V1 前用 5–20 人测试决定方案 A/B |
| 10 | 图鉴默认「全部」而非「本周」 | 种子故事跨周，「全部」能直接看到完整图鉴，演示与首次测试价值优先 | 服务端周口径（weekKey）已实现，切换即可，不算欠账 |

## 3. 已知债务（按影响排序）

诚实清单，每项都有出处，防止「文档说完成、代码有暗坑」：

| # | 债务 | 影响 | 状态 |
|---|---|---|---|
| 1 | 微信开发者工具/真机从未编译 | WXML 编译产物、原生组件、真机性能全部未验证——V0 唯一未闭环验收项 | ⏳ 阻塞级，30 分钟投入 |
| 2 | 合规 Go/No-Go 未核查（方案 §18.2：主体类目/UGC/隐私/备案） | 决定 V1 架构走向；不先查可能整套返工 | ⏳ 阻塞级，云函数编码前 |
| 3 | 发布枚举校验缺失 | 脏枚举值可直接入库破坏聚合 | ✅ V0.2 已修（shared/validation.ts） |
| 4 | 收件箱「全部已读」漏标分页外未读 | 角标显示 0、服务端仍有未读 | ✅ V0.2 已修（markRead all） |
| 5 | 聚合是 O(n×m) 全量扫描；store 每次写操作全量 JSON 落盘 | V0 种子规模无感；**不可照搬进云函数**，V1 换索引/物化 | 🟡 已在架构文档标注迁移对照 |
| 6 | settings 直连 resetState、atlas 直读写 storage 两处分层例外 | 破坏「页面只走 api」纯度 | 🟡 V1 收编进门面 |
| 7 | 页面层复制粘贴（requestId×4、抽屉样式×2、角标×2、舞台 emoji 与 ACTION_MAP 不一致） | 维护成本；emoji 不一致是用户可感知的小瑕疵 | 🟡 P2 清理项 |
| 8 | ~15 处死代码导出 | 误导后续开发者 | 🟡 P2 清理项 |
| 9 | shared 纯函数（time/moderation/rig）零直接单测 | 规则地基无保护 | 🟡 P4 补测 |
| 10 | 邀请 token 弱随机（Math.random + 32 位 FNV hash） | V0 演示可接受；云端必须换加密随机 + 撤销列表 | ⛔ V1 项（架构文档已列入迁移表） |

|---|---|---|

## 5. 对 V1 的启示

从 V0 到 V1，最值得带走的三条：

1. **契约冻结先于云函数编码**。V1 动手前先把「哪些操作必须带 requestId、错误码语义、每机制云端实现方式」从文档变成契约测试，云函数只是实现细节。
2. **白盒测试是迁移债务**。现有测试大量 `loadState()` 直查内部集合，换云函数后全部作废。新用例一律只经 mockApi 响应断言，旧的逐步迁移。
3. **mock 证明不了的，要在云端重新证明**。并发赠礼不超发、事务隔离、真实内容安全接口——这些在 V1 验收清单里是硬项，不能用「mock 已测」替代。

## 6. 产品层面的三点观察

1. **首次用户测试可以提前到 V0**：方案 §19 的四个观察问题（10 秒理解度、无 AI 愿不愿意发、愿不愿意互动、愿不愿意回访）不依赖云函数，现在的可交互预览就够做 3–5 人定性验证——这是成本最低的产品验证，不必等 V1。
2. **匿名外观决策用行为数据**：观察测试者是否因「外观可识别」而放弃匿名，代替提前拍板方案 A/B。
3. **内容安全/举报应并入 V1 主线**而不是留到「上线前」：微信审核 UGC 类目时这是硬条件；V1 设计补充 §7 的规格已经足够开工。
