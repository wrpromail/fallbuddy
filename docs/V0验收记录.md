### 2.2 JSON Schema / 业务不变量

- `incidents.json` 对齐 `schemas/incident.schema.json`（枚举、数组上限、`additionalProperties: false`）。
- `avatars.json` 对齐 `schemas/avatar.schema.json`（调色板、表情、隐私、装备槽）。
- 故事：标题 1–24、正文 1–140、可见圈子非空且存在、状态枚举合法。
- 圈子：每圈恰好 1 个活跃圈主，`ownerId` 与成员关系一致。
- 动作/道具：ID 唯一、时长/上限合理、外观永久且不可转让、互动道具可转让且有 TTL、周补给池只含可发放道具。
- rig：每个装备变体在正/背面都存在；热点数量和坐标在画布内；PNG 尺寸 = bbox × 2 且含透明像素。

### 2.3 WXML 静态检查

没有开发者工具，因此用静态检查兜底：标签配对、`{{ }}` 表达式语法、`bind/catch` 处理函数是否存在、`wx:for` 是否有 `wx:key`、自定义组件是否声明、组件属性名是否能映射到 `properties`。
它不能替代 WXML 编译器，但已经覆盖了最容易在真机编译时才暴露的一类错误。

## 3. 视觉验收与修改记录

V0 验收标准：**朋友在不解释的情况下，能点击骷髅打开故事、看到动画，并理解「这是一个雪友的故事」。**

用「首次访问的普通用户」视角做了一次理解度检查，反馈摘要：

- 能判断是「记录/分享运动经历的小组社群页面」；
- 会主动点「小骷髅头像」「记录一次」「圈子切换」；
- 认为「最热话题部位 尾椎 + 身上贴头像」有幽默感，愿意继续看别人的故事。

据此完成的主要修正：

| 问题 | 修正 |
|---|---|
| 热点头像被骨骼图层盖住（z-index 同层竞争） | `avatar-rig` 建立独立 stacking context；`skeleton-map` 热点层级提高到角色之上 |
| 首屏看不到任何故事卡片，像纯角色页 | 缩小舞台、去掉重复的话题部位卡片、把话题部位收敛成舞台下方一行 |
| 头像被压扁 | chip 模式改为正方形等比 contain，不再按 bbox 拉伸 |
| 两个头像叠得太紧 | 叠放偏移从 16rpx 收到 8rpx，尺寸从 46rpx 提到 54rpx |
| 「送装备」像付费按钮 | 改为薄荷色免费语义，并在说明里写「装备免费、无现金价值」 |
| 角色页背包重复列外观 | 背包只列非外观道具，外观在雪服/帽子/雪镜/护臀区管理 |
| 热点提示不明确 | 文案改为「点身体上的小骷髅头像，看 TA 的那次经历」 |

文档截图：`preview/screens/atlas.png`、`atlas-full.png`、`story.png`、`story-hug.png`、`avatar.png`、`create.png`、`inbox.png`、`group.png`。

## 4. 遗留项与风险

1. **开发者工具/真机未验证**：本机没有微信开发者工具，因此未在模拟器/真机编译。需要复核：
   - TypeScript 编译器插件是否按预期编译所有 `.ts`；
   - 自定义组件 kebab-case 属性绑定（`reduce-motion`、`my-reactions`、`allow-funny`）；
   - 原生 `switch` 尺寸、`scroll-view` 高度、`tabBar` 图标；
   - 真机动画性能与低端机降级。
2. **预览不是运行时**：`preview/index.html` 是本项目自带的一套 DOM 渲染，只用于视觉与交互评审。
3. **V0 无审核**：发布直接 `approved`；举报只弹说明，不写入后台。上线前必须接内容安全、举报处理、管理员审计。
4. **邀请 token 仅本地演示**：没有服务端签名、撤销列表与真实过期清理。
5. **CSS `gap` 兼容性**：大量使用 flex gap，iOS 14.5+ 支持良好；更老的 WebView 可能丢失间距。V1 若需兼容旧机型，应改为 margin。
6. **本机数据**：清缓存或换设备会丢失；V0 没有数据导出/迁移。
7. **合规阻断项**（方案 18.2）仍未解决：个人主体服务类目、UGC 申报、隐私指引、录音/内容检测接口、备案与名称/素材权利核查。
