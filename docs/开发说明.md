# 摔友记 V0 · 开发说明

本文记录 V0 的实现结构、关键规则、素材管线和接云路线。产品与合规边界以
[实施资料包](../shaiyouji_implementation_kit/docs/01_摔友记_产品与技术实施方案.md) 为准。

## 1. 技术栈与分层

```text
pages/* + components/*
        │  只通过 services/api 调用业务
        ▼
services/api.ts（门面，当前指向 mock 实现）
        │
        ├── services/mock/api.ts        业务规则 / 权限 / 限频 / 幂等 / 赠礼事务
        │       ├── shared/mock-build.ts 种子数据组装（相对时间 → 绝对时间）
        │       ├── services/store.ts    wx.setStorageSync 持久化 + 内存回退
        │       └── shared/*             枚举、类型、动作/道具、时间、内容检查
        │
        └── shared/rig.ts  ──►  shared/rig.generated.ts（由素材脚本生成）
```

- 原生 WXML/WXSS/TypeScript，无第三方运行时依赖。
- `tsc` 严格模式做类型检查；小程序侧使用开发者工具的 TypeScript 编译器插件。
- 页面不认识 `wx.cloud`，也不保存业务状态；刷新页面会重新从 `api` 拉取。

### 页面与路由

| 页面 | 路由 | 说明 |
|---|---|---|
| 群体图鉴 | `pages/atlas/index` | 正背面、热点、叠放头像、话题部位、最近故事、热点抽屉 |
| 故事详情 | `pages/story/detail` | 动画舞台、正文与标签、后续时间线、互动、赠礼、分享/举报/撤回 |
| 新建经历 | `pages/incident/create` | 标签 + 标题 + 140 字正文，可见圈子和互动设置 |
| 我的角色 | `pages/avatar/index` | 表情、配色、雪服、帽子、雪镜、护臀、背包、周补给、我的故事 |
| 消息 | `pages/inbox/index` | 未读角标、全部已读、点击回放动画 |
| 圈子 | `pages/group/index` | 成员、邀请 token、复制/分享、退出 |
| 设置 | `pages/settings/index` | 互动权限、减少动效、匿名默认、重置本地数据 |

### 组件

| 组件 | 职责 |
|---|---|
| `avatar-rig` | 按 `rig.generated.ts` 渲染分层角色；`full` / `chip` 两种模式；播放动作；静态降级 |
| `skeleton-map` | 角色 + 正/背面热点 + 叠放头像 + `+N`；向上抛出 `hotspot` 事件 |

| `reaction-bar` | 抱抱/转圈/鼓掌 + 送装备；按当日次数与服务端许可禁用 |
| `item-card` | 背包/赠礼列表的图标、库存、有效期、选中态 |

## 2. 数据模型

V0 用一个 `DbState`（`shared/db-types.ts`）承载文档集合，结构按方案第 9 章：

| 集合 | V0 用途 |
|---|---|
| `users` | 内部用户 + `openid`（仅服务端字段，不返回客户端）+ 偏好 |
| `avatars` | `rigVersion`、配色、装备、表情、隐私、版本号（乐观锁） |
| `groups` / `memberships` / `invites` | 应用内圈子、成员关系、邀请 token（只存 hash） |
| `incidents` / `stories` / `storyUpdates` | 结构化事实、本人确认的叙事、后续时间线 |
| `inventory` / `ledger` | 库存与台账（含每周补给、赠送） |
| `interactions` / `notifications` | 互动事件与站内消息（只存元数据） |
| `weeklyGrants` | `(userId, weekKey)` 唯一，重复领取不重复发放 |
| `operations` | `action + userId + requestId` → 已序列化响应，保证幂等 |

要点：

- **Incident 与 Story 分离**：事实字段（运动、部位、自述原因、情况）不因文案编辑而改变。
- **匿名只影响展示**：`isAnonymous` 只让 `authorName` 变成「匿名雪友」，服务端仍保存 `authorId`，便于删除、风控、举报。
- **一故事多圈子必须逐个勾选**：`visibilityGroupIds` 是数组，`getDetail` 会逐个校验成员关系；分享路径只带 `storyId`，不授予权限。
- **同一部位多个作者**：图鉴按 `bodyParts` 聚合，每个部位最多展示 2 个头像 + `+N`，点击进入该部位的故事列表。
- **同一故事多个部位**：每个部位各计 1 次热点，但故事总数只计 1 条。
- **本周口径**：服务端按 UTC+8 的 ISO 周（`shared/time.ts` 的 `weekKey`）计算，不信任客户端传入的周次。

## 3. 服务端规则（mock 与未来云函数共用同一份契约）

`services/mock/api.ts` 的每个入口都以「当前用户」为身份，**不接受客户端传入的 actorId**。

| 动作 | 校验 |
|---|---|
| `group.getAtlas` | 必须是该圈子的活跃成员，否则 `NOT_MEMBER` |
| `story.getDetail` | 作者本人或该故事可见圈子的成员；撤回/未审核对非作者返回 `NOT_VISIBLE` |
| `story.publish` | 标题 1–24 字、正文 1–140 字、部位 1–3 个、至少 1 个可见圈子且均为成员；手机号/证件号等敏感信息直接 `CONTENT_REJECTED` |
| `interaction.react` | 同圈成员、不能给自己互动、动作存在、作者允许搞笑动作、每人每天对同一故事同一动作最多 3 次、`requestId` 幂等 |
| `inventory.gift` | 同圈成员、收礼人是故事作者、双方都允许收礼、道具可转让、库存 > 0、未过期、每天最多 3 件、`requestId` 幂等；扣减 + 增加 + 台账 + 事件在一次状态变更内完成 |
| `inventory.claimWeekly` | 服务端决定 `weekKey`；同一周重复调用返回同一 `grantId`，不重复发放 |
| `avatar.updateAppearance` | `expectedVersion` 不匹配返回 `CONFLICT`；只能穿已拥有且槽位匹配的外观 |
| `group.createInvite` | 仅圈主/管理员；只返回 `sharePath` 与 token，本地存 hash |
| `group.join` | token 存在、未过期、未达使用上限；退出后可重新加入 |

响应统一为 `{ ok, code, data?, message?, requestId }`，错误码与方案第 10 章一致：
`UNAUTHORIZED / NOT_MEMBER / NOT_VISIBLE / RATE_LIMIT / INTERACTION_DISABLED / INVENTORY_INSUFFICIENT / CONFLICT / NOT_FOUND / VALIDATION_FAILED / CONTENT_REJECTED`。

> 本地实现为保证「重试不重复」会把响应存进 `operations`；云端应由数据库唯一键/事务承担，
> 不能把 `operations` 这类本地缓存当成可靠账本。

## 4. 角色素材管线

素材**不是二进制黑盒**，而是由代码生成，改完执行 `npm run assets` 重新导出：

```text
scripts/art/rig-art.mjs      几何定义：骨骼、表情、雪服、帽子、雪镜、护臀、阴影
        │                    画布 320×480；每个图层声明 bbox
        ▼
scripts/build-assets.mjs     按 bbox 裁剪 → 2x PNG（透明背景）→ miniprogram/assets/rigs
        │                    同时生成 miniprogram/shared/rig.generated.ts
        ▼
shared/rig.ts                resolveRigLayers()：按视图/表情/装备解析出绝对百分比定位
        │                    chip 模式以正方形等比 contain，避免小头像被拉伸
        ▼
avatar-rig 组件               <image> 按百分比叠放，z-index 使用图层顺序
```

- 图层顺序：阴影 → 身体 → 雪服 → 护臀 → 头/表情 → 雪镜 → 帽子。
- 装备槽位：`outfit` / `headgear` / `goggles` / `hip_protector`；变体 key 与道具 ID 一一对应。
- 表情：`happy / surprised / awkward / comfort / cool`；背面无表情。
- 雪镜为半透明镜片，保证表情可见。
- 热点：正面 11 个、背面 12 个（`shared/rig.generated.ts` 的 `hotspots`），与方案 3.3 的 10–12 个一致。
- 锚点：`head / neck / chest / hand_l/r / hip / knee_l/r / foot_l/r / ground`（百分比）。
- 道具图标 96×96、tabBar 图标 81×81，同样由 `icons-art.mjs` 生成。
- 所有素材为原创几何造型，不含品牌 Logo 或联名暗示。

**新增一套雪服**：在 `rig-art.mjs` 的 `outfitFront/outfitBack` 增加颜色分支 → 在 `LAYERS` 的 `variants` 加 key →
在 `shared/items.ts` 增加同 id 的 cosmetic 道具 → `npm run assets` → `npm run validate`。
校验会检查每个变体在正/背面都存在，且背包能对应到 rig 槽位。

## 5. 浏览器开发预览

`npm run preview` 会：

1. 用编译后的 mock 种子在 Node 里跑一遍真实 API（`getAtlas` / `getDetail` / `getInbox` 等）；
2. 把结果、rig 配置、内联 SVG 图层、tabBar 图标合成为**自包含**的 `preview/index.html`。

因此预览与小程序共用同一份素材和同一份种子数据，但**预览自己实现了一套 DOM 渲染与交互**：

- 适合看视觉、点热点、试动画、走发布流程；
- 不证明微信原生组件（`switch`、`scroll-view`、tabBar、真机动画性能）的表现；
- 预览里的发布/互动只写内存，不会改小程序本地存储。

`npm run preview:qa` 用 puppeteer 做交互回归（热点抽屉、故事页、抱抱计数、赠礼、换装、发布、消息、JS 错误、首屏故事卡可见性）；
`npm run shots` 生成 `preview/screens/*` 文档截图。

预览支持 `?screen=atlas|story|avatar|create|inbox|group` 与 `?full=1`（展开滚动容器，方便整页截图）。

## 6. 测试与校验

```bash
npm run verify
```

| 检查 | 覆盖 |
|---|---|
| `tsc -p tsconfig.json` | 严格类型、未使用变量、switch 穿透 |
| `node --test tests/*.test.mjs` | 19 项服务层规则（见验收记录） |
| `export-data.mjs` + `validate_schemas.py` | incident/avatar 与资料包 Schema 对齐；故事长度/可见圈子/成员关系/动作/道具/rig 变体一致性；PNG 尺寸与透明度 |
| `check-assets.mjs` | 每个 rig 图层 PNG 存在且尺寸 = bbox × 2；tabBar/道具图标尺寸 |
| `check-wxml.mjs` | WXML 标签配对、`{{}}` 表达式语法、事件处理函数存在性、`wx:key`、自定义组件声明与属性名（kebab-case → properties） |
| `preview-qa.mjs` | 浏览器端交互、图层、首屏可见性、无 JS 错误 |

`check-wxml.mjs` 是在**没有开发者工具**时尽量提前暴露 WXML 层错误的补充手段：它不能替代 WXML 编译器，但能发现标签不配对、表达式语法错误、事件函数写错、组件未声明、组件属性名不匹配等常见问题。

没有覆盖到的部分：微信开发者工具编译（含 WXML 编译产物、样式隔离、原生组件）、真机手势/性能、真实云端事务并发、内容安全接口。这些需要在 V1 接入时补齐。

## 7. 接入 CloudBase 的路线（V1）

1. 新建 `services/cloud/` 适配器，实现与 `services/mock/api.ts` 相同的函数签名；把 `services/api.ts` 的 `api` 指向它。
2. 云函数统一入口按 `action` 分发；身份只取 `cloud.getWXContext().OPENID`，内部映射 `userId`，不把 OpenID 返回客户端。
3. 所有写操作沿用 `requestId` 幂等：数据库唯一索引 `(action, actorId, requestId)` + 事务。
4. 赠礼按方案 10.1：校验 → 去重 → 事务扣减/增加 → 台账 → 事件/通知；事务不可用时用操作状态机 + 补偿。
5. 邀请 token 只落 hash，设置过期与使用上限；分享路径只带 token。
6. 图片/音频进私有云存储，短时签名访问；音频按保留策略删除。
7. 内容安全：服务端文本/媒体检测 + 人工举报后台；举报人身份不暴露。
8. 环境隔离：dev/test/prod 三套环境；密钥不进仓库；先小范围白名单。
9. AI 只在 V1.1 接入：`ai_jobs` 状态机、预算熔断、单人每日限额、只返回草稿、本人确认后发布。
10. 数据迁移：V0 本地 mock 数据不迁移，V1 从真实身份重新建立；本地故事可作为「示例数据」保留读取。

## 8. 决策记录

- **`shared/` 放在 `miniprogram/` 内**：小程序只能打包 `miniprogramRoot` 下的文件，V0 没有云函数，先把共享代码内聚；V1 引入云函数时再抽根目录 `shared/` 并用构建同步，避免 V0 就引入同步脚本。
- **没有创建 `cloudfunctions/`、`polls/`、`admin/`**：这些都对应 V1 及其之后，按方案“先 T01→T04，再并行 T05/T06”的顺序，V0 不预埋空壳。
- **发布即审核通过**：V0 没有审核后台，`publish` 直接写 `approved`，仅用于本地演示；V1 必须改为 `pending → 检测 → approved`。
- **道具 ID = rig 变体 key**：减少一层映射，校验脚本能直接确认背包外观都有对应图层。
- **默认展示「全部」而不是「本周」**：V0 种子故事跨周，全部视图能直接看到完整图鉴；顶部切换保留了本周口径，统计函数已按服务端周实现。
- **减少动效优先读设置**：`settings.reduceMotion` 会传给 `avatar-rig`，动画降级为静态表情 + emoji，而互动事实仍然落库。
- **动作 `cheer` 也实现了**：方案 V0 写的是 3 个动作，但 5.4 把「鼓掌」列为默认开启能力；实现成本低，保留在动作协议与 UI 中，V0 验收仍以抱抱/转圈/赠礼为核心。
