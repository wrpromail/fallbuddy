# 摔友记｜开发与验收清单

## 阶段 V0：本地可玩原型

- [ ] 建立原生 TypeScript 微信小程序项目，完成构建和本机预览。
- [ ] 绘制一套原创无品牌骷髅角色（正面/背面）。
- [ ] 分离身体、头部、头盔、护具图层，配置统一锚点。
- [ ] 图鉴实现 10–12 个身体热区和正背视图切换。
- [ ] 同一部位多个群友头像叠放，点击展示故事列表。
- [ ] 用 5 条 mock 故事构造身体标记和详情页。
- [ ] 抱抱、转圈、收礼三个动作均能播放，支持静态降级。
- [ ] 在真机上核验点击区和性能，修复遮挡问题。

## 阶段 V1：真实圈子与互动

- [ ] 云开发环境独立区分 dev/test/prod，不把密钥提交仓库。
- [ ] 服务端用微信身份映射内部用户 ID，客户端不接触 OpenID。
- [ ] 圈子邀请、成员加入/退出、权限验证全部通过。
- [ ] 用户可手动发布故事、选择圈子、匿名展示、撤回和删除。
- [ ] 新故事经审核才加入圈子图鉴；撤回后统计正确更新。
- [ ] Avatar 跨设备保存并可换装。
- [ ] 免费周补给每个用户每周只发一次。
- [ ] 背包道具赠送是原子性的；并发、重试不会超发。
- [ ] 动作限制和接收权限生效；可查看互动收件箱。
- [ ] 隐私指引、举报、用户屏蔽、管理员处理最小闭环完成。

## 阶段 V1.1：语音故事与回访

- [ ] 用户主动授权录音，限制音频长度、大小和频率。
- [ ] 音频在私有存储，使用有时效的访问机制。
- [ ] 后台异步 ASR、敏感信息提示、结构化 JSON 校验能完成。
- [ ] AI 结果只作为草稿，必须本人检查、确认后发布。
- [ ] 失败重试次数有上限、可取消、可以退回手动录入。
- [ ] 任务完成后按保留策略清理原始音频与中间产物。
- [ ] 月度预算阈值与单人调用限额可配置、可熔断。
- [ ] 故事能追加后续、按时间线展示、允许撤回。

## 阶段 V1.2：社群投票与完善

- [ ] 群主提名且作者同意的故事才能进入评选。
- [ ] 每人每期每个奖项最多投一票，同票并列。
- [ ] 没有受伤严重度、医疗费用和具体雪道危险排行榜。
- [ ] 卡片分享后，非成员依然无法查看受限内容。
- [ ] 完成 5–20 人小范围真机体验收集与修复。

## 发布 Go/No-Go

- [ ] 核实个人主体能否承载该实际功能及服务类目，不靠文字包装规避。
- [ ] 核实 UGC、内容审核、举报、音频处理和隐私条款。
- [ ] 核实平台音频接口、内容检测接口与云资源费用。
- [ ] 完成名称/视觉素材权利核查。
- [ ] 具备停止新 AI 请求及紧急关闭互动的开关。
- [ ] 非成员越权测试、并发赠礼测试、内容删除测试通过。
