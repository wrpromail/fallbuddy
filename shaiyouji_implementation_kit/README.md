# 摔友记｜本地开发实施资料包

**暂定项目名：摔友记**（仓库代号 `shaiyouji-miniapp` / `fall-buddies`）

这是文档和可引用的协议样例，**不是**已经能够启动的完整小程序代码。请先阅读 `docs/01_摔友记_产品与技术实施方案.md`，从 V0 本地角色与图鉴原型开始实现。

## 文件结构

- `docs/01_摔友记_产品与技术实施方案.md`：完整 PRD、玩法、架构、数据库、AI、成本、安全和迭代计划。
- `docs/02_API_与云函数约定.md`：云函数协议、状态码、关键事务与示例。
- `docs/03_开发验收清单.md`：按阶段的可执行检查点。
- `schemas/incident.schema.json`：事故结构化记录的 JSON Schema。
- `schemas/avatar.schema.json`：角色外观配置的 JSON Schema。
- `config/actions.example.json`：动作、权限与动画资源配置样例。
- `config/items.example.json`：原创趣味物品配置样例。
- `prompts/incident_extract.txt`：LLM 故事提取的约束模板。

## 先实施什么

1. 创建原生 TS 微信小程序项目，在本地使用 mock JSON，不接云资源。
2. 绘制原创 Q 版角色的正、背、装备分层素材；实现热点 10–12 个。
3. 做 5 条虚构故事和 3 个动作（抱抱、旋转、送礼）。
4. 能在手机上完成「点击群体图鉴 → 看故事 → 互动」后，再接 CloudBase 与真实权限。
5. 先有手动文字发布，再做录音/AI；严格控制费用与素材/内容权限。

## 重要边界

- 「圈子」是应用内的受邀群体，不能假定自己自动知道微信群全体成员。
- 内容公开范围必须由作者确认，故事链接不能绕过圈子权限。
- 本人就医/保险经历属于可选亲历分享，不由系统诊断或承诺理赔。
- 道具免费且没有兑换现金的机制；不能用分享换道具等诱导传播方式。
- 在公开发布前，务必核验微信个人主体可用的服务类目、UGC/隐私要求和备案流程。
