# 摔友记云端试用

源码使用微信小程序云函数身份和云数据库事务。默认客户端使用本地演示数据。云端支持创建多个圈子。

## 测试环境部署

1. 在微信开发者工具使用实际测试小程序 AppID 导入仓库，从该小程序关联的测试云环境启用 CloudBase。将环境 ID 填入 `miniprogram/shared/cloud-config.ts`。
2. 建立下列集合，权限全部设为仅服务端可读写。新环境在 `fallbuddy_server_state` 中创建固定文档 ID `pilot-v1`，其中 `snapshot` 为**字符串**字段。已有环境使用原文档，避免覆盖数据。

   ```json
   {"schemaVersion":1,"seededAt":"","users":[],"avatars":[],"groups":[],"memberships":[],"incidents":[],"stories":[],"storyUpdates":[],"inventory":[],"ledger":[],"interactions":[],"notifications":[],"weeklyGrants":[],"invites":[],"operations":{}}
   ```

3. 在仓库根目录运行 `npm run build:cloud`，上传 `cloudfunctions/fallbuddy/` 并在云端安装依赖。运行时用 Node.js 18 或更新版本。设置 `FALLBUDDY_APP_ID` 为测试小程序 AppID。新环境需要自动建立试用圈子时，可设置 `FALLBUDDY_PILOT_OWNER` 为指定圈主的 OpenID。云函数配置需启用 `security.msgSecCheck`。
4. 用户可在圈子页建圈，选择直接加入或审批加入。微信文本安全检查涵盖圈子名称、故事发布与编辑和追加后续的文字。圈主或管理员可暂停本圈子的互动和赠礼。需要暂停整套环境时，设置 `FALLBUDDY_DISABLE_INTERACTIONS=1`。

设置 `FALLBUDDY_DISABLE_POLLS=1` 可暂停提名、同意参选和投票，已有结果仍可阅读，作者仍可退出。

## 数据分区与迁移

| 集合 | 数据 |
|---|---|
| `fallbuddy_server_state` | 分区目录、事务修订号和少量全局字段 |
| `fallbuddy_identity` | 用户、头像、穿搭收藏、屏蔽关系、已注销标识 |
| `fallbuddy_groups` | 圈子、邀请、奖项提名、投票、提前结束的评选和互动开关记录 |
| `fallbuddy_memberships` | 圈子成员关系 |
| `fallbuddy_stories` | 事故、故事、后续、私人草稿、同款关联、举报 |
| `fallbuddy_inventory` | 库存、赠礼和消耗流水、评选纪念章和周补给 |
| `fallbuddy_interactions` | 互动、通知、故事关注、忽略设置 |
| `fallbuddy_operations` | 幂等请求结果、事故发布请求标记、语音任务元数据 |

- 分区用 `字段名-页序号` 作为文档 ID，通过各集合内置的 `_id` 索引定位，目录中保存每个字段的页数。每页 JSON 载荷最多 240,000 字节。需要在控制台按字段及页序号查看时，可建立 `field`、`page` 升序复合索引。
- 升级前在测试环境备份旧 `pilot-v1`。第一笔成功事务将旧快照拆分写入各集合，随后以 `layoutVersion: 2` 的目录替换旧文档。任何一步失败均回滚。升级后检查目录、集合、圈子可见范围、库存和赠礼流水，再放开流量。旧云函数读取旧快照格式，回滚到旧版须同时恢复相应版本的数据。
- 服务仍在每次事务中读取当前全部分区，写入时只提交变化页和目录修订号。扩大试用前在实际 CloudBase 环境测量事务延迟与文档操作量，并据结果将高频查询改为按用户或圈子读取。

## 删除与注销

永久删除会清理事故、故事、后续、关联互动与消息。保留已登记的发布请求指纹，防止弱网重试重新创建已删除的事故。账号注销立即生效。有其他活跃成员的圈子须先转让，只有圈主的圈子随账号清理。注销会删除个人记录和 OpenID，保留防止旧账号自动重建的不可逆标识，以及已到账道具的最小流水。流水中注销用户一侧的身份字段会清空。

## 验收

`npm run test:cloud` 使用内存事务和替身内容审核，运行打包后的真实业务代码。云端和本地演示状态各自保存。

测试需要两个授权微信账号和两台设备。分别记录测试账号角色、客户端版本及每一步结果。

1. 用圈主账号发邀请。圈员提交申请，审批前打不开图鉴，审批后能打开圈内记录。
2. 用圈主账号发布一条测试事故。圈员打开旧链接查看，圈主改为仅自己可见后，圈员从同一链接重新打开会收到权限提示。
3. 两台设备登录同一测试账号，对同一事故、私人草稿和角色分别发起编辑。先在一台保存，再在另一台保存。检查冲突提示、表单输入和角色试穿是否保留。用弱网重试同一次发布，检查图鉴只有一条记录。
4. 两台设备恢复使用各自的账号。用圈员账号领取周补给并赠送一件道具，双击或重试只扣一次。圈主的背包收到一件道具，角色仍穿着原来的装备。
5. 在测试环境检查内容安全拒绝和举报处理。圈主隐藏被举报记录后，圈员从旧链接访问或互动会收到权限提示。
6. 确认撤销的邀请无法新增申请，已有申请仍可处理。转让圈主后分别验证退圈保留和移除可见权限。验证双向屏蔽和恢复后的图鉴与消息，并回放抱抱检查两位角色和装备。退出并保留故事后修改正文，确认原受众仍可查看。
7. 用专用测试账号验证注销和删除。确认旧链接无法打开、原发布请求重试无法重新创建事故、旧账号无法继续访问，而另一方已收下的道具仍在。

## 可选语音服务

小程序的「用语音起草」支持本机回听及手动填写。自动转写需要在服务端配置下表。文本整理服务可独立选用。仓库没有预置处理商、密钥或计费账号。

| 环境变量 | 含义 |
|---|---|
| `FALLBUDDY_VOICE_ENABLED` | 值为 `1` 时允许接受新的转写任务 |
| `FALLBUDDY_VOICE_BASE_URL` | 兼容服务的 HTTPS API 基址，须包含服务商要求的版本前缀 |
| `FALLBUDDY_VOICE_TOKEN` | 仅保存在云函数环境的处理商凭证 |
| `FALLBUDDY_ASR_MODEL` | 通过 `/audio/transcriptions` 处理中文 MP3 的模型 |
| `FALLBUDDY_DRAFT_MODEL` | 可选，通过 `/chat/completions` 摘录标题及正文。返回内容须能在转写原文中找到 |
| `FALLBUDDY_VOICE_MONTHLY_LIMIT` | 全环境每个北京时间自然月最多受理的任务数，必须为正整数。另有每人每日 3 次限制 |

客户端经确认发送最长 90 秒的单声道 MP3。服务端根据音频帧复核长度。每次受理最多调用一次转写和一次可选摘录。预算采用任务数量上限，实际金额随所选模型和计价规则变化。提交前取消可停止发送，已送交处理商的任务取消后会丢弃结果，已占额度保留。处理商的计费、超时和保留期限需要在选用后单独核对。

转写结果随本次请求返回给本人，临时音频在客户端关闭面板时清理。服务端仅保存任务元数据，下次语音写事务会清理超过 32 天的历史元数据。云函数与客户端调用的超时应覆盖转写及可选摘录耗时，单次外部 HTTP 请求的时限为 22 秒。功能验证可用替身处理商运行 `npm run test:cloud`。
